## 6. Defects found and fixed

| ID | Severity | Found by | Problem | Fix |
|---|---|---|---|---|
| D-1 | High | image build | pinned `packaging` 26.3 conflicted with Streamlit (< 25) | regenerated `constraints.txt` with a resolver |
| D-2 | High | TC-SYS-01 | DVC 3.59 incompatible with `pathspec` 1.x | pinned `pathspec==0.12.1` in the ML image |
| D-3 | High | TC-SYS-01 | original data repository returns 404 | configurable URL template; switched to the public mirror |
| D-4 | High | TC-SYS-01 | LightGBM missing `libgomp1` in the slim image | installed `libgomp1` |
| D-5 | Medium | TC-SYS-09 | CPU oversubscription (BLAS threads) → timeouts under load | `OMP/OPENBLAS/MKL_NUM_THREADS=1`, 3 model-server workers |
| D-6 | Medium | TC-SYS-10 | MLflow at 90 % of its 1 GB memory limit | 2 gunicorn workers, 1.5 GB limit |
| D-7 | Medium | TC-UI-14 | Streamlit "magic" rendered a ternary expression → page error | `magicEnabled = false`; explicit if/else |
| D-8 | Low | TC-SYS-05 | promotion gate compared a full-precision value with a rounded tag | compare both at 5 decimals |

## 7. Known limitations
* The backend runs one process (in-memory outcome tracking), so throughput is bounded at ~10 req/s on
  this VM. Moving pending predictions to Redis would allow several workers.
* Retraining on unchanged data is skipped by DVC by design; a real retrain needs new data or new
  parameters.
